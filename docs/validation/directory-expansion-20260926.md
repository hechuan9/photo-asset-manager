# 小箭头展开延迟排查

用户明确报告：小箭头展开子目录开始快、随后变慢，不是点击目录名加载照片。

## 现场证据

- NAS 本机对同一目录连续请求 20 次：首次 88 ms，其余 2.9–3.3 ms；此样本没有服务端递增延迟。
- Mac 到 NAS 请求同一子目录 5 次：48.8、2.4、6.5、2.6、4.4 ms。独立测得资产和计数接口约 275–485 ms，但小箭头不会调用这些接口，因此不能用它们解释本问题。
- 操作期间主线程采样 15 秒：91.7% 样本等待事件，未出现持续布局热点；包含自动化辅助功能查询的开销。这次未复现用户报告的持续变慢，不能据此否认现象。
- 原 UI 将一个根目录的全部已展开后代递归放进单个 List row 的 VStack；辅助功能树也显示为一个大行。随着展开增加，行内内容和布局范围增加，这是明确的结构风险，但采样尚未证明它是唯一根因。

## 修复与验证方向

将可见目录扁平为各自独立的 List 行，让列表按行管理视图；保留服务端按需请求、已读取子目录缓存、刷新折叠和失败重试。记录目录请求耗时与返回数量，不记录文件路径或凭据。后续在实际卡顿时用请求日志与主线程采样区分网络等待和界面布局。

这次不修改 NAS 文件系统、扫描任务或照片，不以增加缓存后端或暂停扫描代替诊断。
