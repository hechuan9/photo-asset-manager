# Mac 与 iOS 目录版本缓存验证

两端已接入 schema 5 的 revision / isUpdating 协议。每个连接独立使用共享有界内存缓存，最多 20 个查询和 10,000 个资产条目；切换查询先恢复已有分页，再按目录版本校验。稳定且版本相同的查询不重新获取资产列表。修改中同一版本的自动刷新最多每 30 秒一次，最终版本变更立即更新；手动刷新不受此限制。

## 验证结果

- `swift test --package-path shared`：27 项通过，覆盖完整查询身份、稳定状态匹配、LRU 与资产容量、目录参数编码及完整 64 位版本。
- `swift test --package-path macos`：28 项通过。A→B→A 恢复已加载分页，列表与计数请求不增加；验证修改中节流、最终版本刷新、混版重同步、重叠分页去重。
- `swift test --package-path ios`：14 项通过，其中图库 9 项、既有目录 5 项。覆盖缓存命中、查询切换、修改中节流、失败保留内容、分页版本、凭据切换、旧请求隔离、并发请求去重、修改后缓存失效。
- 两端完整 Xcode Debug 工程构建通过，关闭代码签名。iOS 使用 generic iOS Simulator；macOS 使用 generic macOS，并设 `ONLY_ACTIVE_ARCH=NO` 统一主程序与共享包的 arm64 / x86_64 架构。第一次 Mac 本机目的地构建因目标架构不一致失败，统一架构后通过，无需改工程配置。
- 轻量版本核验不显示图库或目录行加载指示；已有空列表也保留内容状态。实际内容刷新失败保留已有照片并显示错误。
- `git diff --check` 通过。

这是本地实现、自动测试和编译验证；未上传新 TestFlight，未在真机安装验收。本轮未变更 NAS 后端。列表缓存仅在当前应用会话内保留，图片仍使用既有磁盘缓存。分页跨版本时重新取第一页以避免混合快照；正常同版本刷新恢复已加载范围。
