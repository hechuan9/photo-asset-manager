# Keeps：统一服务端资料库

2026-09-26 确定采用 NAS Server 中枢与 HTTP API。此决策替代此前“NAS / 本地暂存”双区域设计；运行架构与接口见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 产品模型

Keeps 只有一个当前连接的资料库。全部照片、精选、评分、标签及回收站由 Server 统一管理，Mac 与 iPhone 通过同一 HTTP API 查询和修改。客户端无需 SMB 挂载、理解本机到 NAS 的路径映射或直接读取原片。

文件系统是服务器内部的存储来源。既有原片继续保留在原来的 NAS 目录中，Server 直接读取这些目录；不因界面和协议调整删除、移动或覆盖原片。容器在 NAS 内的只读目录映射与客户端网络挂载是不同概念。

## 导航与主界面

默认进入“全部照片”，侧栏提供“全部照片”“精选”“回收站”。移除“本地暂存”区域及待接入空页面。

“服务器来源”是可展开的辅助浏览区域，默认收起。用户展开后通过 HTTP 查询服务器目录树；目录只用于筛选照片和定位来源，不代表独立资料库。主图库查询不需要先成功读取目录树，来源请求失败不能阻止已有索引照片显示。

“管理来源与任务”打开服务端来源配置、扫描状态和失败重试。路径输入明确是服务器原片根目录下的相对路径，不接受把 Mac 路径当作 NAS 本地路径的解释。所有追踪和处理都在服务端执行，关闭客户端不影响任务。

点击来源目录默认包含下级内容，可切换为仅当前目录。切换全部照片、精选、回收站或目录范围时清除之前的筛选和选择，避免错误批量修改。照片预览仅使用服务器返回的 HTTP URL。

## 数据与交互语义

- 来源目录由服务端真实目录查询返回，包含已登记但尚未索引或为空的目录；不从照片反推目录树。
- `hasChildren` 表示服务器目录是否存在可见直接子目录；叶子目录没有展开箭头。
- `photoCount` 是数据库中包含后代、按资产去重且不在回收站的已索引照片数，不表示磁盘总文件数，也不受当前筛选影响。
- 读取目录或照片时显示加载状态；失败明确报错并可重试，不能把离线显示为空资料库。
- 左键目录箭头展开或折叠，左键名称选择；右键只打开该目标菜单。键盘左/右方向键保留原生树形导航。目录菜单不提供删除、移动或覆盖原片。
- 照片回收站及停止追踪只修改服务器记录。

## HTTP 边界

业务调用使用 HTTP/HTTPS JSON API 与 Bearer 认证；预览使用服务端签名下载 URL。Mac 和 iPhone 共用 KeepsAPI。客户端只保留当前查询、选择、分页、表单、连接设置和可丢弃的网络图片缓存。

不引入 gRPC、第二套本地资料库、客户端目录监听或离线业务写入。任务进度沿用 HTTP 查询。接口及错误以服务端实现和共享客户端测试为准。

## 尚未实现的能力

本地文件未来作为显式上传来源，不作为独立资料库。上传会话、断点续传、重名/重复处理、服务端写入目的地及完成判定尚需设计实现；当前没有上传入口，不会自行接入或扫描本机文件。

逻辑相册应独立于来源目录，加入相册不移动原片；当前尚未实现相册 API。当前扫描器支持照片扩展名，视频索引与 sidecar 完整发现/归属仍未实现，不宣称媒体递归索引完整。

## 验收边界

验证两端通过 HTTP 浏览与整理，客户端不需要挂载，来源失败不影响索引照片查询，切换范围不串数据，离线有明确错误，服务端任务独立于客户端，原片无删除、移动或覆盖。线上验收另需真实 NAS 和设备证据，单元测试通过不代表已部署。

## macOS 视觉基准（2026-09-26）

视觉参考为新版 Lightroom 桌面版，而非 Lightroom Classic。Keeps 使用深灰中性画布、44 pt 顶栏搜索及侧栏开关、268 pt 目录面板、可收起的 292 pt 信息面板和 48 pt 右侧信息工具轨。保留 Keeps 品牌、统一资料库与服务器来源导航和服务器能力边界。

照片按原始比例排成等高行，以 1 pt 细缝的无圆角网格展示；完整行自动铺满可用宽度，末行不额外放大，去掉常驻文件名卡片，通过悬停查看文件名，评分和标记叠放在照片角落。底栏提供网格 / 单张查看、评分、留用标记和缩略图尺寸调节。信息面板默认收起，让照片占据主要空间；搜索始终可见，评分、颜色、标签和排序位于可展开的筛选区。界面外观固定为深色，原片预览按原比例完整显示。

目录树继续使用原生控件，保持箭头展开、名称选择、右键菜单及键盘导航语义。仅呈现已有功能，不显示未实现的 Adobe 编辑、云同步或导出工具。

macOS 目录与图库之间使用原生可拖动分割条，目录宽度为 200–480 pt；目录滚动条以浮层呈现并自动隐藏。图库滚动到底部自动加载下一页；若底部在请求期间出现，请求结束后继续加载，失败时停止并显示错误。

隐藏目录通过目录右键设置或取消，子目录继承父目录隐藏状态；全库、精选、回收站、搜索和上级目录浏览过滤隐藏内容。只有明确进入隐藏目录或其子目录时显示对应内容；单独设置隐藏的后代仍需进入后查看。“显示”菜单可开关过滤。目录树保留入口，标记由服务器保存；不加密或修改原片。

## iOS 照片浏览（2026-09-28）

iOS 采用系统“照片”的浏览顺序：轻点照片进入全屏，左右轻扫切换，底部缩略图带跳转，单击显示或隐藏控制栏，双击及双指缩放，原始缩放状态下向下轻扫返回图库。长按照片打开针对该照片的菜单；信息按钮打开可关闭的信息与整理面板，保留版本、评分、标记、标签和逻辑回收站能力。

图库提供大图、中图、密集三档，通过双指捏合或显示菜单切换。大图以每行三张常见竖图为基准，支持一横两竖混排；中图以每行五张竖图为基准。同一行照片面积相等，保留完整宽高比，横图上下允许留白。密集档为每行九张小方块，裁切仅作用于图库缩略图；打开照片始终完整显示。切换档位尽量保留当前浏览位置，不显示常驻文件名卡片。全屏仍使用服务端预览，不代表下载相机原片或实现像素级原图编辑。后台更新不会因重载首页而中断正在浏览的后续分页照片。

### iOS 全屏时间轴修订

图库以旧在上、新在下的顺序展示，首次进入定位最新照片；接口仍从最新页取数，客户端反向组行，向顶部续载旧页。照片延伸到状态栏与底部控制区背后，标题、选择按钮、图库选项和底部“图库 / 精选集 / 搜索”使用浮层，保留原比例完整画面。精选集提供现有留用与回收站查询；独立搜索面板按文件名或相机查询。缺失拍摄时间时明确标注添加日期。

“选择”进入多选模式，提供留用、移入回收站和恢复；全选仅针对已加载照片，回收站操作确认后只修改数据库。浏览旧照片时暂停自动刷新，返回最新位置恢复；显式刷新保留已加载的页数。
